# Happy Desktop vs Buzz

Block launched [Buzz](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together) ([source](https://github.com/block/buzz), [engineering deep-dive](https://engineering.block.xyz/blog/buzz), [HN discussion](https://news.ycombinator.com/item?id=48995213)) a day before we announced Happy Desktop. We read the codebase.

We agree on more than we disagree on: open source, self-hosted, agents as first-class participants, one server that owns the truth, and the principle that an agent should never assume human credentials. Here is where the designs split.

| area | happy (2) | buzz |
| --- | --- | --- |
| agent identities | identity == context where you run: channel history + agent state + sandbox | named keypair personas (fizz, honey, bumble) you drag between channels, times everyone on the team |
| running agents | the server owns execution via [Rig](https://github.com/slopus/rig), our shared runtime; every channel gets its own docker sandbox with checkpoint/resume, background terminals, subagents | the relay stores agent profiles but runs nothing; the model runs wherever someone runs a harness |
| sync | telegram-style: server sequence + `getDifference`, revoked state gets removed, realtime is just a hint to come sync | replay the signed event log: capped replay, timestamp cursor; once delivered, it's yours forever |
| permissions | the grant IS the tool surface, so you can't attempt what you weren't given | agent carries full buzz-cli + a private key; allowed = discovered by attempting |
| secrets | attached, not pasted: bound to an agent or channel, injected into the sandbox at run time, never prompt text | `BUZZ_PRIVATE_KEY` straight in the agent's env; per-call approval bypassed by default |
| plugins | containers behind a capability-only API: MCP tools for agents, app surfaces for the UI, permissions per install | no installable surface, so you extend via MCP servers, workflows, or new event kinds baked into relay + clients |
| self-hosting | `npx happy2`, one process orchestrates everything (docker only for the sandboxes) | docker compose: rust relay + postgres + redis + minio |

Two more differences worth naming. Documents in Happy Desktop are collaborative, with incremental updates, presence, and agents proposing while humans approve. Buzz has single-author notes with last-write-wins, so a concurrent write just loses. And app previews: port sharing is itself a plugin in Happy Desktop, letting an agent expose a sandbox port at a URL under your domain, to an audience of your choice. Buzz has no equivalent.

Where Buzz wins today: the UI. Ours is worse, for now. They mostly copied Slack, but copied it well, and the onboarding is genuinely nice. The hard part is the overall UX of supervising agents, not solved by anyone yet.
