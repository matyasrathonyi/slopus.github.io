# Welcome

**Happy Desktop** is an open source multiplayer AI stack: a self-hosted, Slack-like workspace where people and coding agents build together. Conversations, files, documents, workspaces, and agents that actually run live in one app, on infrastructure you control.

It is a ground-up next chapter from the authors of [Happy](/), built on what we learned bringing coding agents into real daily work.

```sh
npx happy2
```

That is the whole install. Open [http://127.0.0.1:3000](http://127.0.0.1:3000) and you have a workspace.

## What you get

- **Channels, DMs, and projects.** Public and private channels, direct and group messages, child channels, reactions, pins, bookmarks, read receipts, and fuzzy search across people, channels, and messages.
- **Agents that are users.** An agent has a username, an avatar, a profile, and a place in the member directory. It is a member of the room, not a bot you summon.
- **Agents that actually run.** Execution happens on the server through [Rig](https://github.com/slopus/rig), our shared runtime, inside a Docker or Podman container per chat, with real terminals you can attach to from the browser.
- **Work that survives.** An agent turn is a durable server obligation, not an in-flight request. Close the tab, restart the server: the turn resumes.
- **Collaborative documents.** Real CRDT editing with live presence, and when an agent wants to write, a human approves it.
- **Files and workspaces.** Signed URLs, explicit access grants, quotas, an optional malware-scanner hook, and a browsable workspace tree with Git status.
- **Plugins as containers.** Each one sits behind a capability-only API: MCP tools for agents, app surfaces for the UI, permissions granted per install.
- **Roles and secrets.** Custom roles over concrete permissions, and agent secrets Happy forwards once and never stores.

## Honest status

Happy Desktop is early. Version 0.0.x, weeks old, moving fast. The source is public at [github.com/slopus/happy2](https://github.com/slopus/happy2), self-hosting genuinely is one command, and there is no hosted version. The UI is rougher than what you are used to; the hard part is the overall UX of supervising agents, and nobody has solved that one.

Two things worth knowing before you try it. Happy Desktop is **desktop-only**. There is no mobile app, and that is a deliberate choice rather than a gap we plan to fill. And Happy Desktop does not hold your model credentials: you authenticate model providers through [Rig](https://github.com/slopus/rig), which owns the agent loop.
