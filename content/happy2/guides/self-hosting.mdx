# Self-Hosting

Happy Desktop is self-hosted by design. `npx happy2` runs the complete app (server, web app, and the private Rig runtime) as one process. Docker is only needed for agent sandboxes.

## Configuration

Behavior comes from a TOML file, resolved in this order:

1. `--config /path/to/happy2.toml`
2. `HAPPY2_CONFIG=/path/to/happy2.toml`
3. `./.happy2/happy2.toml`, when it exists
4. Built-in defaults

Configuration is **partial**: Happy Desktop recursively merges your fields over the defaults, so exposing the listener to your network is this much file:

```toml
[server]
host = "0.0.0.0"
```

Relative database, file, plugin, key, and agent paths resolve from the directory where Happy Desktop starts, not from the TOML file's directory.

## Behind a reverse proxy

For a deployment such as `https://happy.example.com`, the listener can stay on `127.0.0.1`. Set the public origin and the exact number of proxies in front of you:

```toml
[server]
public_url = "https://happy.example.com"
trusted_proxy_hops = 1

[jwt]
issuer = "https://happy.example.com"
```

`trusted_proxy_hops` is what decides how far Happy Desktop trusts forwarded headers, so it must match your actual topology. Binding `server.host = "0.0.0.0"` is only necessary when another machine or container connects directly.

## Authentication

**Exactly one** authentication method may be enabled at a time: password (the default), magic link, OIDC, or Cloudflare Access. Set `auth.password.enabled = false` before enabling another one.

```toml
[auth.password]
enabled = true

[auth.magic_link]
enabled = false
# from = "Happy Desktop <noreply@example.com>"

[auth.oidc.example]
enabled = false
# discovery_url = "https://id.example.com/.well-known/openid-configuration"
# client_id = "happy2"
# client_secret_env = "HAPPY2_OIDC_EXAMPLE_CLIENT_SECRET"

[auth.cloudflare_access]
enabled = false
# team_domain = "https://team.cloudflareaccess.com"
```

SMTP credentials for magic-link auth always come from the environment (`EMAIL_SMTP_HOST`, `EMAIL_SMTP_PORT`, `EMAIL_SMTP_USER`, `EMAIL_SMTP_PASSWORD`) and never from the TOML file. OIDC client secrets are named by environment variable rather than written inline.

## Keys and secrets

Session tokens are RS256-signed. If you do not supply keys, an `all` or `auth` server generates a 3072-bit key pair and writes `HAPPY2_JWT_PRIVATE_KEY_B64` and `HAPPY2_JWT_PUBLIC_KEY_B64` into the private `.env` beside the selected TOML path, which is `./.happy2/.env` by default, created with mode `0600`. It also generates the password pepper and the integration secret when those are missing.

Real process environment values take precedence over that file. Back it up and keep it private:

- Replacing the JWT keys **invalidates every existing session token**.
- Replacing the password pepper **prevents existing password hashes from verifying**.

You can supply PEM files instead:

```toml
[jwt]
private_key_path = "/run/secrets/happy2-jwt-private.pem"
public_key_path = "/run/secrets/happy2-jwt-public.pem"
```

An `api`-only server must be given the matching public key, because it does not generate a signing pair.

## Splitting the deployment

`server.role` selects what an instance does:

- `all`: authentication plus the product API. The default.
- `auth`: authentication only, as a separately deployed identity service.
- `api`: validation only, using a public key you provide.

`happy2 web` serves only the SPA and proxies `/v0` to a backend given by `HAPPY2_BACKEND_URL`. It has its own CLI options rather than reading the server TOML.

## Files and quotas

```toml
[files]
provider = "local"
directory = ".happy2/files"
max_upload_bytes = 536870912
per_user_quota_bytes = 0   # zero disables the quota
server_quota_bytes = 0
# malware_scanner_command = "/usr/local/bin/clamscan"
malware_scan_failure_mode = "deny"
```

If you configure a malware scanner, decide deliberately whether a scan failure should `deny` or `allow` the upload.

## Rate limits and idempotency

Both are on by default and worth reviewing before you expose the server:

```toml
[security.rate_limit]
enabled = true
reads_per_minute = 1200
writes_per_minute = 300
auth_per_minute = 30
```

For the complete TOML reference, see the [server documentation](https://github.com/slopus/happy2/blob/main/packages/happy2-server/README.md).
