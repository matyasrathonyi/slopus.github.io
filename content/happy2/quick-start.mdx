# Quick Start

Happy (2) requires **Node.js 24 or later**, and **Docker or Podman** on your `PATH` if you want agents. That is the boundary agent code runs inside, so server setup will not finish without one.

## Run the whole stack

```sh
npx happy2
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). One process orchestrates the server, the web app, and the private Rig runtime that executes agents.

The first run walks you through setup: create the bootstrap account and your profile, pick the sandbox provider, build the base agent image (streamed live, and it survives a restart if you close the tab), create your default agent, and choose who is allowed to register.

Model providers are authenticated through Rig, not through Happy (2). Happy never handles your API keys.

## Keep it running

Run it in the background without installing an operating-system service:

```sh
npx happy2 daemon start
npx happy2 daemon stop
```

The daemon writes `happy2.pid`, the combined `happy2.log`, and the error-only `server-error.log` under `./.happy2`. Stopping it terminates the daemon process tree and removes the PID file.

To survive reboots:

```sh
npx happy2 service start
npx happy2 service stop
```

On macOS this installs a per-user LaunchAgent without `sudo`, starting when you log in. On Linux it writes and prints `./happy2.service` along with the exact `sudo` commands to install it as a systemd unit, and it never runs `sudo` itself. Add `--config ./happy2.toml` to `service start` to pin an explicit configuration file.

## Where your data lives

Everything Happy (2) creates goes under `.happy2` in the directory where you started it:

| Path | Contents |
| --- | --- |
| `.happy2/happy2.db` | SQLite database: channels, messages, documents, agent state |
| `.happy2/files` | Uploaded files |
| `.happy2/workspaces` | Agent working directories |
| `.happy2/rig` | The private Rig runtime socket and token |
| `.happy2/plugins` | Installed plugins |
| `.happy2/.env` | Generated JWT key pair, password pepper, integration secret (mode `0600`) |
| `.happy2/happy2.toml` | Configuration, when you create one |

Back up `.happy2/.env` and keep it private. Replacing the JWT keys invalidates existing sessions; replacing the password pepper stops existing password hashes from verifying.
