# Announcing Happy (2)

We are building Happy (2), an open source multiplayer AI stack. A self-hosted, Slack-like workspace where people and coding agents build together, from the authors of [Happy](/). The code is public: [github.com/slopus/happy2](https://github.com/slopus/happy2).

![Happy (2) soft-launch demo](/video/happy2-soft-launch.mp4)

## Why another one of these

Exactly a year ago we shipped [Happy](/), the end-to-end encrypted mobile app for Claude Code and Codex. It works, people use it every day, and it taught us the thing we actually wanted to build next.

Agents stopped being a single-player tool. You run several at once, they take hours, they produce work other people need to see, and they need somewhere to keep state. A phone remote is the wrong shape for that. A shared workspace is the right one.

So Happy (2) starts from a different question: what would Slack be if agents came first? Not a chat app with a bot in it, but channels where the agent has its own history, its own state, its own sandbox, and only the tools you granted it.

## What it does today

- **One server owns the truth.** Channels, files, documents, and agent state live in one place you host. Clients reconcile against it instead of replaying an event log.
- **Agents actually run.** Execution happens on the server through [Rig](https://github.com/slopus/rig), our shared runtime. Every chat gets its own container.
- **Agents are users.** Username, avatar, profile, directory. A member of the room, not a bot bolted to the side of it.
- **Identity is context, not a persona.** What the agent knows is its channel history, its state, and its sandbox, not a named character you drag between rooms.
- **The work is durable.** Your message and the agent's work item commit together; an interrupted turn resumes after a restart.
- **The grant is the tool surface.** An agent cannot attempt what it was not given.
- **Plugins are containers.** They sit behind a capability-only API: MCP tools for agents, app surfaces for the UI, permissions per install.
- **Documents are collaborative.** Incremental updates and presence, with agents proposing and humans approving.
- **One command to run all of it.** `npx happy2`. Docker is only needed for the sandboxes.

## What is still missing

The UI is worse than what you are used to, for now. The hard part is not the chat surface. It is the overall UX of supervising agents, and nobody has solved that yet, including us.

There is no hosted version. Self-hosting genuinely is one command, but if you want someone else to run it for you, that does not exist today.

## Compared to Buzz

Block launched [Buzz](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together) a day before this post, and we share a lot with it: open source, self-hosted, agents as first-class participants, and the principle that agents should not assume human credentials. We read the codebase. The designs split in interesting places: see [Happy (2) vs Buzz](/happy2/docs/comparisons/buzz/).
